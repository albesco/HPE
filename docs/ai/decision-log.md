- 2026-05-20 | SwimXYZ visibility semantics | Treat SwimXYZ `z` as a 3D coordinate, not as keypoint visibility/confidence | The active conversion pipeline documents `z` as a Blender-space coordinate and reconstructs COCO/MMPose visibility from image position instead of consuming `z` | In the prepared pipeline, visibility is currently collapsed to `v=0` for missing/border-clamped points and `v=2` for retained points; `v=1` occlusion is not preserved unless a separate source field is introduced.
- 2026-05-15 | VitPose++ checkpoint policy | Keep only latest periodic checkpoint plus best validation checkpoint | Each VitPose++ checkpoint is about 11 GB, so retaining every epoch is too expensive while best/latest are enough for resume and model selection | Launchers/config generation use `checkpoint_config.max_keep_ckpts=1`, `create_symlink=True`, and `evaluation.save_best='AP'`.
- 2026-05-15 | VitPose++ resume robustness | Ignore invalid checkpoint metadata config during resume while still loading model/optimizer/epoch state | A resumed checkpoint contained an unparsable `meta.config`; failing only on metadata blocked otherwise valid incremental training | `runner.resume` is wrapped so invalid metadata config is tolerated; future resume tests should still verify model state and metrics continuity.

- 2026-05-16 | VitPose++ checkpoint policy | Keep best validation checkpoint plus the latest three periodic checkpoints (max_keep_ckpts=3) | Continuing beyond epoch 30 may overfit, so training needs a small rollback window without retaining every 11 GB checkpoint | Future launchers/config generation preserve best_AP_*.pth, latest.pth, and the two previous periodic checkpoints while deleting older periodic checkpoints.
